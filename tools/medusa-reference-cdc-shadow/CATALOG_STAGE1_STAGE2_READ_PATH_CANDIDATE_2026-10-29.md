# Catalog stage 1 → inventory/price stage 2 CDC read path candidate

**Status:** COMBINED-CLONE SAMPLE PASS; business-wide conformance and live cutover NOT RUN. This is not an active analytical binding.

`probe-inventory-price-cdc-only-candidate.py` reads product and variant fields from the governed stage-1 CDC projection. Its stage-2 inventory/price fields come from the governed stage-2 CDC projection. It checks both configured Debezium connectors address the same isolated `postgres:5432/medusa` service with distinct pinned slots and topic prefixes. The catalog query reads rows, its short-lived quality lease and current applied offsets in one repeatable-read transaction. A missing/expired lease, incomplete table/topic coverage, mismatched digest/offset, changed applied offset after lease, source/epoch mismatch or broken product–variant relation prevents a `PASS_SAMPLE_ONLY` result.

The test still discovers one sample ID and publishable API key from the isolated clone DB, and uses Medusa Store API only as an independent comparison oracle. This does not constitute a production CDC-only read path. Two profiles may have different coverage epochs and Kafka offsets; the probe does not equate those offsets to one global transaction boundary. The two installers/verifiers now accept the exact `funnelmetry_cdc_combined_shadow_*` project prefix in addition to their original, separate prefixes. Each still owns a distinct role/publication/slot/topic prefix and state file. For the current probe the project is pinned to `funnelmetry_cdc_combined_shadow_c1`.
