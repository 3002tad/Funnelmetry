# Medusa CDC primary integration

Status: CDC-13 reference cutover. `funnelmetry.integration.yaml` is the source of truth for the Medusa reference CI planner. The planner validates the pinned Medusa host, emits a reviewable patch on the already selected integration branch, and verifies the resulting files. It does not provision logical replication or change a running CDC connector.

The manifest must declare the order v2, catalog and inventory/price CDC profiles and `bindings.medusa_backend: []`. A new checkout receives Browser SDK/storefront behavioral hooks plus the three CDC profile files. Existing checkouts receive a guarded migration: the installer deletes its old order subscriber/dispatcher, backend package dependency, occurred-at helper and CDC v1 profile when present; it refuses unknown ownership or altered CDC source identifiers. The old CI `rollback-plan` commands and the `rollback_target: native_order_placed` setting are retired. No new `medusa.order_placed` message producer is generated.

For a new integration branch based on the pinned Medusa `main` storefront, the installer creates `store-search` and wires its query and opaque interaction ID through the store page, template and product request. The server hook emits the search outcome without waiting for delivery. The existing V2 storefront path remains supported; partial search wiring is rejected. Plan capabilities report search/cart as enabled only when the required host files are present and patchable.

The CDC profile files retain their original names and `SHADOW_ONLY` technical status for compatibility with the separately operated CDC-11 source/target provisioning tools. The **analytical authority** is the approved `reference.medusa.order_recorded_state.v2` current-state contract, with coverage epoch and quality gate. `SHADOW_ONLY` in the file is not permission to re-enable the native adapter. Browser SDK and storefront `cart.item_added`/`behavior.search_submitted` still use Source Ingress and HTTPS Event Feed until Gateway is implemented.

Use `node src/cli.mjs plan --config <manifest> --project <checkout> --out <outside-checkout-dir>` and `node src/cli.mjs verify --config <manifest> --project <checkout>`. CI applies the patch on the existing non-main branch. Logical replication slots, publications, Kafka topics and analytical state remain operator-owned; CDC recovery uses the existing epoch/quality procedures, never a rollback to the old message adapter or Admin API catalog pull.
